Folha de Referência 03: Matriz Decisória de Motores Analíticos

Lakehouse vs. Data Warehouse vs. Eventhouse vs. Fabric SQL Database (Domínio 1)

Matriz Comparativa de Motores para o Exame DP-700

Característica Lakehouse Data Warehouse Eventhouse Fabric SQL Database
Perfil Primário Engenharia de dados Spark, ciência de dados e machine learning. BI corporativo, analistas de negócios e data warehouse relacional. Telemetria IoT, streaming em tempo real, logs e eventos de máquina. Aplicações operacionais OLTP leves integradas ao OneLake.
Linguagens Principais PySpark, Scala, Spark SQL, R (e SQL read-only via Endpoint). T-SQL completo (DDL e DML: INSERT, UPDATE, DELETE, MERGE). KQL (Kusto Query Language) e subset de T-SQL. T-SQL completo para operações OLTP transacionais.
Escrita via T-SQL ❌ Não (SQL Analytics Endpoint é estritamente Read-Only). ✅ Sim (Suporte pleno a comandos DML transacionais). ⚠️ Parcial (.ingest / KQL Update Policies). ✅ Sim (Com suporte completo a índices OLTP).
Segurança Granular Apenas no SQL Analytics Endpoint (mas causa Direct Lake Fallback). ✅ Nativa no T-SQL: RLS, CLS e Dynamic Data Masking (DDM). ✅ Políticas de Row-Level no KQL e restrições de tabela. ✅ RLS, CLS, DDM e encriptação nativa do SQL Server.
Zero-Copy Clones Deep e Shallow clones via comando Delta Spark. ✅ Nativo via instrução CREATE TABLE AS CLONE OF. Políticas de retenção e cache gerenciadas pelo motor. Pontos de restauração transacionais (PITR).
Regra de Ouro DP-700 Escolha quando a equipe for fluente em Python/Spark ou precisar de arquivos semiestruturados/não estruturados. Escolha quando for exigido suporte a transações multi-tabela ACID em T-SQL e segurança centralizada de RLS/CLS. Escolha quando a exigência for subsegundo para milhões de eventos por segundo e buscas indexadas de logs. Escolha para microsserviços e apps OLTP que necessitem de espelhamento contínuo zero-ETL no OneLake.
