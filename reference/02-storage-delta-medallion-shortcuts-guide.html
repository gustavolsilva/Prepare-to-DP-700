Folha de Referência 02: Storage, Delta Lake, Medallion & Zero-Copy

Cheat-sheet oficial para o Exame DP-700 (Domínio 1 e Domínio 2)

1. Arquitetura de Armazenamento: Parquet & Delta Lake

Componente Tipo Como Funciona / Regra de Ouro Impacto no Exame DP-700
Apache Parquet Storage Formato colunar binário com Row Groups, Column Chunks e compressão por dicionário (Snappy/ZSTD). Base universal de todos os itens do Fabric no OneLake.
_delta_log Protocol Pasta de commits atômicos em JSON ordenados sequencialmente (ex: 000000.json), com checkpoints periódicos em Parquet. Garante propriedades ACID; quem lê a tabela consulta o log primeiro antes dos dados.
Time Travel Feature Consultar snapshots históricos usando TIMESTAMP AS OF ou VERSION AS OF. Permite auditoria e recuperação de erros sem restaurar backups.
VACUUM Maintenance Exclui fisicamente arquivos tombstoned obsoletos. Limiar padrão = 7 dias (168 horas). Executar com retenção zero destrói permanentemente o Time Travel!

2. Arquitetura Medallion no Microsoft Fabric

Camada Padrão de Dados Objetivo & Responsabilidade Itens Fabric Recomendados
Bronze (Raw) Dados brutos, imutáveis, cópia exata da origem (append-only). Preservar histórico completo sem perda de fidelidade, com colunas de metadados (_ingestion_timestamp). Lakehouse Files / Lakehouse Tables (Delta Parquet).
Silver (Cleansed) Dados validados, enriquecidos, desduplicados e tipados. Ponto único da verdade corporativa para analistas e cientistas de dados (SCD Tipo 1 e 2). Fabric Lakehouse (Notebooks PySpark / Dataflows Gen2).
Gold (Curated) Modelos dimensionais Star Schema (Fatos e Dimensões) e agregações prontas. Consumo analítico de alta performance por relatórios do Power BI e modelos semânticos executivos. Fabric Lakehouse / Fabric Data Warehouse.

3. Integração Zero-Copy: Shortcuts vs. Database Mirroring

Funcionalidade Origens Suportadas Mecanismo Técnico Quando Escolher no DP-700
OneLake Shortcuts ADLS Gen2, Amazon S3, Google Cloud Storage, Dataverse, outros Lakehouses. Ponteiros simbólicos (links virtuais). Não há cópia nem movimentação de dados em repouso. Quando os dados já estão em formato Parquet/Delta em outra nuvem e deve-se evitar duplicação.
Database Mirroring Azure SQL Database, Azure Cosmos DB, Snowflake. Replicação contínua e assíncrona baseada em CDC (Change Data Capture) gravando em Delta Parquet no OneLake. Quando se precisa de dados operacionais relacionais quase em tempo real sem impacto no banco OLTP.
