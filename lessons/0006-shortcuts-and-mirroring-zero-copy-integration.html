Eliminando Silos e Custos de Egress: Shortcuts e Mirroring no OneLake

Antes do Microsoft Fabric, conectar um data lake corporativo a dados legados em outras nuvens (AWS S3 ou Google Cloud) ou bancos transacionais exigia construir rotinas de ETL pesadas que copiavam terabytes de dados diariamente pela internet, incorrendo em tarifas abusivas de tráfego de rede (Egress fees) e duplicação desnecessária de armazenamento.

O Microsoft Fabric introduziu uma nova filosofia de arquitetura: Zero-Copy Integration.

Topologia de Integração Zero-Copy: Shortcuts vs. Database Mirroring

1. OneLake Shortcuts (Ponteiros Virtuais)

Mapeia dados onde eles já residem sem transferir a cópia física.

  • Destinos Suportados: ADLS Gen2, Amazon S3, Google Cloud Storage, Dataverse e Workspaces internos do Fabric.
  • Mecanismo: Objeto de metadados JSON no OneLake que aponta para o bucket ou container remoto.
  • Visibilidade: Tratado de forma transparente pelos motores Spark, SQL Endpoint e Power BI Direct Lake.

2. Database Mirroring (Zero-ETL CDC)

Sincronização contínua de bancos relacionais operacionais para o OneLake.

  • Bancos Suportados: Azure SQL Database, Snowflake, Azure Cosmos DB.
  • Mecanismo: Lê os logs de transação do banco via Change Data Capture (CDC) de baixo impacto.
  • Armazenamento: Converte e grava automaticamente em tabelas Delta Parquet prontas para consumo em segundos.

Delegação de Identidade e Segurança em Shortcuts

Ao criar um Shortcut para fontes externas (como Amazon S3 ou ADLS Gen2), a autenticação pode ser realizada via:

  • Workspace Identity / Managed Identity: A identidade do workspace assume as permissões de acesso ao recurso sem expor chaves de API fixas.
  • Role ARN (Amazon Web Services): Permite delegação cruzada de segurança onde a Microsoft assume temporariamente a role IAM definida na AWS.
  • Controle de Caching: Opcionalmente, pode-se habilitar cache de leitura de curta duração para otimizar acessos repetitivos de relatórios.

🌱 O que são Atalhos (Shortcuts) e Espelhamento (Mirroring)?

Pense no Shortcut como o atalho que você cria na área de trabalho do seu computador. O arquivo pesado está guardado lá na outra pasta (ou na nuvem da Amazon), mas você clica no ícone da sua mesa e abre o arquivo instantaneamente sem precisar criar uma cópia dele.

Pense no Mirroring como um espelho mágico. Toda vez que um cliente faz uma compra no banco de dados da loja, o espelho reflete essa mudança no OneLake em poucos segundos, sem que ninguém precise rodar um programa manual de cópia.

🌿 Como Criar um Shortcut no Lakehouse Passo a Passo

Para integrar um bucket do Amazon S3 ou container ADLS Gen2 no Fabric:

  1. Abra o seu Lakehouse no Fabric.
  2. Clique com o botão direito na pasta Tables ou Files e selecione New shortcut.
  3. Selecione a fonte externa (ex: Amazon S3 ou Azure Data Lake Storage Gen2).
  4. Insira a URL do bucket (ex: s3://meu-bucket/vendas/), informe as credenciais de conexão e confirme.
  5. A pasta aparece imediatamente como uma tabela Delta local pronta para consultas em PySpark e T-SQL!

🛠️ Cenários de Prova DP-700: Shortcuts vs. Copy Data & Mirroring Constraints

⚠️ Padrão Clássico de Questão da Certificação: "A empresa possui 40 TB de dados históricos em formato Delta Lake armazenados em um bucket do Amazon S3. A equipe precisa realizar consultas analíticas no Fabric minimizando os custos de armazenamento e evitando qualquer duplicação física de dados. O que você deve fazer?"

Solução Invariável: Criar um OneLake Shortcut apontando para o bucket do Amazon S3. Se o enunciado mencionar "Criar um pipeline no Data Factory para copiar os dados periodicamente", descarte imediatamente essa alternativa pois ela duplica dados e viola o requisito de custo mínimo.

Requisitos Técnicos Mandatórios do Mirroring:

  • O banco de dados operacional de origem precisa ter a opção de Change Data Capture (CDC) ativa e suportada.
  • No caso do Azure SQL Database, o nível de serviço deve ser General Purpose ou superior (Standard S3 ou superior).
  • A sincronização de metadados e arquivos Delta gerados pelo Mirroring fica disponível no catálogo do OneLake e é consultável via T-SQL e Direct Lake.

⚙️ Arquitetura Interna: Resolução de Metadados e Latência de Rede

Quando um nó executor de Spark executa um Scan sobre uma tabela mapeada via OneLake Shortcut para o S3:

  1. O driver do Fabric consulta o metadado do Shortcut no OneLake para resolver o endpoint remoto e as credenciais temporárias do IAM Role.
  2. O plano de execução empurra a leitura diretamente contra as APIs REST do S3 (GetObject).
  3. Os blocos colunares do Parquet são transmitidos diretamente para a memória do executor Spark.
  4. Se o cache do Shortcut estiver habilitado, blocos frequentemente lidos são mantidos no SSD NVMe local do nó de computação do Fabric por até 24 horas, acelerando leituras subsequentes.

🏛️ Visão Estratégica & FinOps: Economia Brutal em Taxas de Egress

Empresas multinacionais que operam em ambientes multi-cloud (AWS + Azure) gastam dezenas de milhares de dólares por mês em taxas de transferência de saída (Egress fees) ao sincronizar data lakes completos.

Com OneLake Shortcuts:

  • Apenas os bytes das colunas efetivamente consultadas (graças ao Column Pruning do Parquet) trafegam pela rede, gerando uma redução de até 85% no tráfego de dados entre nuvens.
  • Elimina-se o pagamento de armazenamento duplicado em duas nuvens simultâneas.

Exercício Prático: Criar Atalhos (Shortcuts) no OneLake e Mirroring Zero-Copy

Guia passo a passo para executar diretamente na plataforma em nuvem do Microsoft Fabric (ou em simulação local).

📋 Cenário do Laboratório

A empresa possui dados legados no Amazon S3 e no Azure Data Lake Storage Gen2. Em vez de criar pipelines caros de cópia, você criará atalhos (Shortcuts) no OneLake permitindo consultas diretas em subsegundo.

🔑 Pré-requisitos para Execução no Portal

  • Navegador web moderno (Edge, Chrome ou Firefox).
  • Acesso ao portal Microsoft Fabric (app.fabric.microsoft.com).
  • Capacidade ativa do Fabric (licença Fabric Trial gratuita ou capacidade corporativa).
  • Um Workspace configurado no modo de capacidade Fabric.
1

Criar um Atalho (Shortcut) para o Amazon S3

  1. Abra o Lakehouse lh_global_enterprise.
  2. Passe o mouse sobre a pasta Tables, clique nos três pontos (...) e selecione Novo atalho (New shortcut).
  3. Selecione o provedor Amazon S3.
  4. Preencha o caminho do bucket (ex: s3://corp-telemetry-data/) e as credenciais de acesso.
  5. Nomeie o atalho como s3_telemetria_shortcut e clique em Criar.
🔒 https://app.fabric.microsoft.com/groups/lh_global_enterprise/shortcuts
📸 Captura do Portal: Assistente de criação de atalhos (Shortcuts) para fontes internas OneLake, ADLS Gen2 e Amazon S3.
2

Consultar o Atalho Diretamente sem Duplicação

  1. Abra o Notebook Spark vinculado ao Lakehouse.
  2. Leia os dados da tabela criada pelo atalho exatamente como se fosse uma tabela local:
  3. df_s3 = spark.table('s3_telemetria_shortcut'); display(df_s3.limit(10))
  4. Observe que o OneLake busca os dados sob demanda sem transferir armazenamento permanente.
⚠️ Atenção para o Exame DP-700:
Pegadinha de Exame: Os atalhos não copiam arquivos físicos; eles apenas criam metadados apontando para a fonte externa. Se a credencial na AWS/Azure expirar ou os dados forem deletados no bucket de origem, o atalho no Fabric apresentará falha de leitura.

Pontos Críticos para a Prática e para o Exame DP-700

📝 Síntese dos Pontos Críticos Aprendidos:

  1. Conceito de Shortcuts (Atalhos): Ponteiros lógicos no OneLake que referenciam dados em fontes externas (ADLS Gen2, Amazon S3, Dataverse) sem duplicar armazenamento.
  2. Zero-Copy Architecture: Consultas analíticas executadas no Fabric leem os dados diretamente na nuvem de origem, reduzindo custos de tráfego de rede e tempo de ETL.
  3. Shortcuts Internos: Permitem reutilizar tabelas entre diferentes Lakehouses e Warehouses sem quebrar limites de workspace ou duplicar dados.
  4. Mirroring no Fabric: Replicação automática e contínua de bancos relacionais (Cosmos DB, Azure SQL, Snowflake) em formato Delta Parquet no OneLake.
