O Espectro da Orquestração no Fabric: De No-Code a Grafos DAG em Código

No Microsoft Fabric, a orquestração e movimentação de dados atende tanto a engenheiros que precisam de controle algorítmico rigoroso via código quanto a analistas que operam via interfaces visuais intuitivas.

As 4 Ferramentas de Ingestão e Orquestração: Matriz de Aplicação

Recurso Interface / Linguagem Poder Computacional Cenário Recomendado na Prova DP-700
Copy Job Wizard No-Code Simples Cópia ponto-a-ponto Carga rápida de tabelas brutas para a camada Bronze sem regras de transformação.
Dataflows Gen2 Power Query M / Low-Code Visual Mashup Engine com Staging Lakehouse Transformação visual para analistas de negócios, limpeza tipada e mesclagem de tabelas.
Data Factory Pipelines Canvas Visual de Atividades Orquestrador de Atividades e Triggers Fluxo de controle (If, ForEach, Until), chamadas de WebHooks, tolerância a falhas e agendamento.

A Arquitetura Interna do Staging nos Dataflows Gen2

Um diferencial arquitetural crítico introduzido nos Dataflows Gen2 é a habilitação automática do Staging Lakehouse.

Nas versões legadas do Power Query, grandes volumes de dados sofriam com limitações de memória do gateway. No Fabric:

  1. Os dados brutos são extraídos e descarregados imediatamente no Lakehouse de Staging oculto do workspace.
  2. As transformações complexas de junção e agregação são processadas diretamente pelo motor Polaris T-SQL ou Spark sob o capô (Query Folding avançado).
  3. Os dados finais higienizados são comitados na tabela de destino (Lakehouse ou Data Warehouse) em formato Delta Parquet limpo.

🌱 Qual é a Diferença Entre Pipeline e Dataflow Gen2?

Pense no Dataflow Gen2 como o "preparador dos ingredientes na cozinha". Ele limpa as folhas estragadas, corta os legumes, remove números nulos e junta tabelas usando uma tela cheia de botões amigáveis (Power Query).

Pense no Data Factory Pipeline como o "maestro do restaurante". Ele não cozinha diretamente, mas avisa: "Se o caminhão com os ingredientes chegou com sucesso, mande o assistente limpar; se falhou, mande um e-mail de alerta para o gerente!".

🌿 Orquestração Prática: Estruturando um Pipeline Completo

Em um projeto corporativo típico no Fabric, as atividades são encadeadas seguindo as regras de dependência de status:

  • Upon Success (Verde): Executa a próxima etapa apenas se a anterior finalizar com sucesso.
  • Upon Failure (Vermelho): Dispara alertas para o Teams ou chama uma Azure Function para registrar o incidente.
  • Upon Completion (Azul): Executa comandos de limpeza de arquivos temporários, independentemente do sucesso ou falha da atividade anterior.

🛠️ Armadilhas de Prova DP-700: mssparkutils.notebook.runMultiple & Staging

⚠️ Padrão Crítico do Exame DP-700: "Você possui 15 notebooks de limpeza de dados em PySpark. O notebook Silver_Vendas só pode iniciar após os notebooks Bronze_Clientes e Bronze_Produtos terminarem. Você precisa executar esses notebooks em paralelo minimizando o tempo total e sem criar um pipeline visual no Data Factory. O que você deve utilizar?"

Resposta Oficial: Utilizar a biblioteca utilitária mssparkutils.notebook.runMultiple(DAG) passando um dicionário com o array de atividades e suas dependências explícitas.

Desabilitando o Staging no Dataflow Gen2:

Por padrão, o Dataflow Gen2 usa o Lakehouse de Staging. No entanto, se o destino final for exatamente o mesmo Lakehouse onde a transformação está sendo salva e os dados forem muito pequenos, é possível desabilitar o staging para economizar uma gravação intermediária de disco.

⚙️ Arquitetura Interna: Execução Paralela e Limites de Concorrência

Ao invocar mssparkutils.notebook.runMultiple, o Fabric aloca sessões subordinadas (child sessions) no Spark Pool.

O parâmetro concurrency (ex: "concurrency": 4) limita o número de workers simultâneos competindo pela alocação de vCores do pool. Isso impede que múltiplos notebooks paralelos esgotem as Capacity Units (CUs) da capacidade, evitando que outras tarefas do workspace entrem em fila de espera (throttling ou enfileiramento de jobs).

🏛️ Visão Estratégica & FinOps: Produtividade vs. Custo Computacional

A escolha da ferramenta de ingestão impacta diretamente no tempo de entrega (Time-to-Market) e no consumo de CUs:

  • Dataflows Gen2: Aumentam a produtividade da equipe em até 4x para cargas simples, mas consomem mais CUs devido à camada de mashup do Power Query.
  • Pipelines + Spark Otimizado: Exigem engenharia de dados especializada, mas são altamente eficientes em custo para volumes massivos de dados (terabytes/petabytes).

Exercício Prático: Orquestrar Pipelines de Dados com Atividades DAG e Dataflows Gen2

Guia passo a passo para executar diretamente na plataforma em nuvem do Microsoft Fabric (ou em simulação local).

📋 Cenário do Laboratório

Construir um pipeline de dados corporativo no Data Factory encadeando uma atividade de extração rápida (Fast Copy), um Dataflow Gen2 de higienização e um Notebook Spark final para alimentar a camada Gold.

🔑 Pré-requisitos para Execução no Portal

  • Navegador web moderno (Edge, Chrome ou Firefox).
  • Acesso ao portal Microsoft Fabric (app.fabric.microsoft.com).
  • Capacidade ativa do Fabric (licença Fabric Trial gratuita ou capacidade corporativa).
  • Um Workspace configurado no modo de capacidade Fabric.
1

Criar o Pipeline de Dados no Data Factory

  1. No workspace, selecione + Novo item > Data pipeline.
  2. Nomeie como pl_daily_enterprise_etl e clique em Criar.
  3. No menu de atividades superior, adicione uma atividade Copy data.
  4. Adicione uma atividade Dataflow Gen2 e conecte a seta verde (Sucesso) da Copy data nela.
  5. Adicione uma atividade Notebook conectada à saída com sucesso do Dataflow Gen2.
🔒 https://app.fabric.microsoft.com/groups/pipelines/pl_daily_enterprise_etl
📸 Captura do Portal: Canvas visual de orquestração no Data Factory montando o Grafo Acíclico Direcionado (DAG).
2

Depurar e Monitorar a Execução das Atividades

  1. Na barra de ferramentas, clique em ▶ Depurar (Debug).
  2. Acompanhe na aba inferior Saída (Output) o status de cada nó da DAG, taxa de transferência e tempo de execução.
  3. Configure um gatilho de agendamento (Schedule Trigger) diário para às 02:00 AM UTC.
⚠️ Atenção para o Exame DP-700:
No exame DP-700: Fast Copy acelera cargas maciças de dados para o Lakehouse; Dataflows Gen2 trazem o poder do Power Query M com suporte a transações e staging em Lakehouse; e Pipelines fornecem controle de fluxo com If Condition, ForEach e tratamento de erros.

Pontos Críticos para a Prática e para o Exame DP-700

📝 Síntese dos Pontos Críticos Aprendidos:

  1. Data Pipelines (DAG): Orquestrador corporativo com suporte a dependências (Sucesso, Falha, Conclusão), atividades de fluxo (ForEach, If Condition, Until) e parâmetros dinâmicos.
  2. Fast Copy no Data Factory: Acelera transferências massivas de bancos relacionais e arquivos para o Lakehouse com paralelismo otimizado em rede.
  3. Dataflows Gen2: Transformação visual e baseada em código Power Query M com suporte a transações e staging automático em Lakehouse.
  4. Tratamento de Exceções: Pipelines devem implementar branches de falha enviando notificações via Web Activity ou integrando com o Azure Monitor.
