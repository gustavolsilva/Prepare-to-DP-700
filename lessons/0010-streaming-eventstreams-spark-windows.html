Engenharia de Streaming no Fabric: De Eventstreams sem Código a Spark Distribuído

O processamento contínuo de dados é indispensável em ecossistemas de dados modernos para telemetria IoT, detecção de fraudes financeiras e monitoramento de servidores.

No Microsoft Fabric, a ingestão e agregação em tempo real é dividida entre duas soluções:

  • Fabric Eventstreams: O roteador central de eventos gerenciado, com conectores integrados para Azure Event Hubs, IoT Hub, Apache Kafka e aplicativos REST customizados. Permite criar transformações visuais (filtros, projeções e janelas) roteando saídas simultâneas para o Eventhouse (KQL) e o Lakehouse (Delta Parquet).
  • Spark Structured Streaming: Motor distribuído em código PySpark no Lakehouse para transformações avançadas com controle refinado de estado e políticas de descarte via withWatermark.

As 4 Janelas Temporais de Streaming Obrigatórias no Exame DP-700

Tipo de Janela Comportamento Temporal Sintaxe PySpark Cenário Canônico de Prova
Tumbling Window Blocos de tamanho fixo sem sobreposição e contíguos. window(ts, '5 minutes') Totalizar transações financeiras a cada 5 minutos exatos (00:00-00:05, 00:05-00:10).
Hopping Window Janelas fixas que se sobrepõem com avanço periódico. window(ts, '10 min', '5 min') Calcular a média móvel de temperatura dos últimos 10 minutos, recalculada a cada 5 minutos.
Sliding Window Avaliação contínua disparada a cada novo evento que entra. Limiar de tempo móvel Alerta de segurança: disparar alarme se houver 3 tentativas de login falhas nos últimos 2 minutos.
Session Window Agrupamento dinâmico baseado em período de inatividade. session_window(ts, '15 min') Agrupar cliques de navegação de um usuário na loja virtual, fechando a sessão após 15 min inativo.

Tratamento de Dados Atrasados: O Papel do withWatermark

Em redes sem fio e ambientes IoT, sensores frequentemente perdem conectividade e transmitem lotes de dados com minutos ou horas de atraso.

Se o motor Spark mantivesse todas as janelas passadas abertas indefinidamente na memória aguardando eventos atrasados, o cluster sofreria erro de estouro de memória (OutOfMemoryError). A cláusula withWatermark("event_time", "15 minutes") informa ao Spark: "Aguarde eventos atrasados até 15 minutos em relação ao maior carimbo de tempo visto. Qualquer evento que chegar com atraso superior a 15 minutos deve ser descartado."

🌱 O que são Janelas de Tempo em Streaming?

Imagine que você está na beira de uma avenida contando quantos carros passam:

  • Tumbling: Você zera o seu cronômetro a cada 5 minutos exatos e anota o total em um caderno. Cada bloco de 5 minutos é isolado.
  • Hopping: Você anota quantos carros passaram nos últimos 10 minutos, mas faz essa anotação a cada 5 minutos (uma anotação se sobrepõe à anterior).
  • Watermark: É a tolerância que você dá para aquele carro que ficou preso no semáforo e demorou para passar pelo seu ponto de contagem!

🌿 Implementação em PySpark Structured Streaming

# Leitura em streaming a partir da tabela Delta Bronze
df_stream = spark.readStream.table("bronze_telemetria")

# Agregação com tolerância a dados atrasados (Watermark de 10 min) e janela Tumbling de 5 min
df_aggregated = df_stream \
    .withWatermark("timestamp", "10 minutes") \
    .groupBy(
        window("timestamp", "5 minutes"),
        "sensor_id"
    ) \
    .agg(avg("temperatura").alias("media_temp"))

# Escrita contínua na tabela Silver com checkpointing gerenciado
query = df_aggregated.writeStream \
    .format("delta") \
    .outputMode("append") \
    .option("checkpointLocation", "/Files/checkpoints/silver_stream") \
    .toTable("silver_telemetria_5min")

🛠️ Armadilhas do Exame DP-700: Tumbling vs. Hopping & Eventstreams Routing

⚠️ Questão Clássica de Prova: "Uma empresa de logística precisa gerar relatórios de média móvel de velocidade de frotas considerando os últimos 15 minutos de dados, emitindo uma nova média calculada a cada 5 minutos. Qual tipo de janela temporal deve ser configurado no fluxo de streaming?"

Resposta Invariável: Hopping Window (duração de 15 minutos com salto/hop de 5 minutos). Se o enunciado afirmasse que os períodos "não possuem sobreposição entre si", a resposta seria Tumbling Window.

Recurso Derived Streams no Eventstreams:

No Fabric Eventstreams, você pode criar múltiplos Derived Streams (fluxos derivados) a partir da mesma fonte bruta. Isso permite rotear, por exemplo, eventos com código de erro crítico para o Eventhouse para alertas imediatos em KQL, e simultaneamente gravar todos os eventos brutos no Lakehouse para auditoria em batch.

⚙️ Arquitetura Interna: Gerenciamento de Estado do Spark (State Store)

Em agregações com janelas temporais, o Spark Structured Streaming mantém tabelas de estado em memória (RocksDB State Store Provider ou HDFS State Store).

O withWatermark é o gatilho que executa o State Cleanup: ele calcula a marca d'água atual como max(event_time) - delay_threshold. Quando uma janela termina antes da marca d'água atual, o motor comita a janela, grava o resultado no sink Delta e expurga os registros do State Store, mantendo a pegada de memória do executor constante e previsível ao longo de meses de execução contínua.

🏛️ Visão Estratégica & FinOps: Eventstreams vs. Clusters Spark Contínuos

Manter um cluster Spark 24/7 rodando Structured Streaming consome nós dedicados e gera uma despesa contínua de Capacity Units (CUs).

Para fluxos de ingestão padrão:

  • Fabric Eventstreams: Opera em arquitetura 100% serverless nativa. Você paga apenas pelas mensagens trafegadas, reduzindo o custo de infraestrutura contínua em até 70% quando comparado a manter notebooks Spark permanentemente ligados.

📋 Cenário do Laboratório

Capturar fluxos de telemetria IoT de turbinas em tempo real, aplicar filtros de anomalia térmica e agregação temporal usando janelas de streaming antes de persistir no OneLake.

🔑 Pré-requisitos para Execução no Portal

  • Navegador web moderno (Edge, Chrome ou Firefox).
  • Acesso ao portal Microsoft Fabric (app.fabric.microsoft.com).
  • Capacidade ativa do Fabric (licença Fabric Trial gratuita ou capacidade corporativa).
  • Um Workspace configurado no modo de capacidade Fabric.
1

Criar o Eventstream no Microsoft Fabric

  1. No workspace, selecione + Novo item > Eventstream.
  2. Nomeie como es_iot_telemetry_stream e abra o designer visual.
  3. Adicione uma Nova fonte (New source) selecionando Azure Event Hub ou Custom endpoint.
  4. Adicione um operador de transformação para filtrar Temperature > 80 e agregar por janela Tumbling de 1 minuto.

Roteamento Duplo: Eventhouse e Lakehouse Bronze

  1. Conecte uma saída para o Eventhouse para permitir alertas imediatos no dashboard.

Pontos Críticos para a Prática e para o Exame DP-700

📝 Síntese dos Pontos Críticos Aprendidos:

  1. Microsoft Fabric Eventstreams: Hub centralizado sem código para captura, roteamento e transformação em tempo real de fluxos contínuos de eventos.
  2. Janelas Tumbling: Janelas temporais de tamanho fixo e contíguas que nunca se sobrepõem (ex: agregando a cada bloco de 5 minutos).
