Aceleração de Transformações em Lote: Motores Polaris e Spark

A transformação de dados em lote no Fabric combina comandos relacionais de alta velocidade no Data Warehouse com a flexibilidade distribuída do Apache Spark no Lakehouse.

Comandos Canônicos de Transformação Batch no Microsoft Fabric

Comando / Recurso Ambiente Finalidade Técnica Diferencial no OneLake
COPY INTO Data Warehouse Ingestão ultraveloz de arquivos externos (Parquet, CSV) via T-SQL. Paralelismo de nós distribuídos sem necessidade de cluster Spark ativo.
MERGE INTO Warehouse / Lakehouse Upsert atômico (insere novos e atualiza modificados em 1 instrução). Commit ACID único no _delta_log, eliminando estados inconsistentes.
mergeSchema=true Lakehouse (Spark) Schema Evolution automático para absorver novas colunas de entrada. Adiciona metadados de colunas no Delta sem quebrar tabelas existentes.
CREATE TABLE AS CLONE OF Data Warehouse Criação instantânea de cópias de tabelas para homologação e testes. Zero-Copy: compartilha os mesmos arquivos Parquet físicos no OneLake!

A Revolução do Zero-Copy Table Clone no Warehouse

Em bancos de dados relacionais tradicionais, criar um ambiente de testes para homologar um relatório exigia duplicar 10 terabytes de dados, aguardar horas de cópia e pagar duas vezes pelo armazenamento.

No Fabric Data Warehouse, o comando CREATE TABLE Tabela_Homolog AS CLONE OF Tabela_Prod; é executado em menos de 2 segundos. O motor Polaris apenas duplica os ponteiros de metadados no catálogo. Nenhuma linha física de dados é copiada no OneLake até que uma instrução DML altere especificamente um arquivo no clone.

🌱 O que Significa Clonar Sem Cópia (Zero-Copy Clone)?

Imagine que você tem uma biblioteca com 10.000 livros raros. Se você quiser que um colega estude sem riscar os seus livros, você não precisa comprar outra biblioteca inteira!

Você apenas cria uma ficha dizendo: "O colega está autorizado a ler os mesmos livros na mesma estante". Se o colega quiser escrever uma anotação em uma folha, apenas essa folha nova é guardada para ele. Isso é o Zero-Copy Clone: rapidez instantânea e custo zero de espaço extra!

🌿 Como Usar COPY INTO com Armazenamento Externo no Warehouse

Para carregar um lote de arquivos Parquet de uma conta ADLS Gen2 diretamente no Fabric Warehouse: 

COPY INTO dbo.FactSales
FROM 'https://meuaccount.dfs.core.windows.net/raw/vendas/*.parquet'
WITH (
    FILE_TYPE = 'PARQUET',
    CREDENTIAL = (IDENTITY = 'Workspace Identity')
);

🛠️ Armadilhas do DP-700: Schema Mismatch e Clonagem em Testes

⚠️ Cenário Recorrente no Exame: "Um job em PySpark grava dados de telemetria em uma tabela Delta na camada Silver. Uma atualização no firmware dos sensores adicionou duas novas colunas ('battery_health' e 'signal_quality'). As próximas execuções do notebook começam a falhar com erro de esquema incompatível (AnalysisException: schema mismatch). Qual opção do Spark deve ser configurada para permitir a ingestão contínua?"

Resposta Oficial: Adicionar a opção .option("mergeSchema", "true") na operação df.write.format("delta").mode("append").saveAsTable(...). O Delta Lake aplicará o Schema Evolution de forma segura sem corromper as partições antigas.

Regra para Ambientes de Testes:

Se a questão pedir para "Criar um ambiente isolado para o time de qualidade testar queries destrutivas sem duplicar os custos de armazenamento e sem impactar os relatórios em produção", a resposta correta no Warehouse é CREATE TABLE ... AS CLONE OF.

⚙️ Arquitetura Interna: Copy-on-Write vs. Merge-on-Read no Delta

O motor relacional Polaris do Fabric Warehouse e o Spark implementam o padrão Copy-on-Write (CoW) para transações MERGE INTO.

Durante o plano de execução:

  1. O motor realiza um Inner Join entre a tabela alvo e a tabela fonte para identificar quais arquivos Parquet contêm linhas que sofreram modificação.
  2. Apenas os arquivos Parquet que possuem tuplas correspondentes são reescritos em novos arquivos (com os novos valores atualizados e novas linhas anexadas).
  3. Os arquivos antigos são marcados como tombstoned no _delta_log e permanecem disponíveis para Time Travel até que o comando VACUUM seja executado.

🏛️ Visão Estratégica & FinOps: Governança Ágil com Clones

Em grandes empresas, provisionar réplicas de bancos de dados analíticos para auditoria ou desenvolvimento consumia semanas de planejamento de infraestrutura e aumentava os custos de armazenamento em nuvem.

Com Zero-Copy Table Clones no OneLake:

  • O tempo de provisionamento de ambientes de homologação cai de 6 horas para 3 segundos.
  • O custo de armazenamento é zero até que alterações pontuais ocorram, acelerando o ciclo de lançamento de novos relatórios analíticos (Time-to-Market).

📋 Cenário do Laboratório

Executar rotinas analíticas em lote no Fabric e aplicar cópias de zero-custo via comandos CLONE TABLE no Warehouse para testar atualizações destrutivas em ambiente isolado sem duplicar dados.

🔑 Pré-requisitos para Execução no Portal

  • Navegador web moderno (Edge, Chrome ou Firefox).
  • Acesso ao portal Microsoft Fabric (app.fabric.microsoft.com).
  • Capacidade ativa do Fabric (licença Fabric Trial gratuita ou capacidade corporativa).
  • Um Workspace configurado no modo de capacidade Fabric.
1

Criar um Clone de Tabela (Zero-Copy Clone)

  1. No Fabric Warehouse, abra uma nova consulta SQL.
  2. Execute o comando: CREATE TABLE dbo.FactVendas_Homolog AS CLONE dbo.FactVendas;
  3. Observe que o clone é criado em subsegundo, apontando para os mesmos arquivos físicos Delta Parquet no OneLake.
🔒 https://app.fabric.microsoft.com/groups/dw/clone-table
📸 Captura do Portal: Criação de Clone de Tabela (Zero-Copy) para homologação rápida de código analítico.
2

Testar Alterações Isoladas no Clone

  1. Execute alterações pontuais ou deletes de teste na tabela clonada: DELETE FROM dbo.FactVendas_Homolog WHERE Ano = 2024;
  2. Consulte a tabela original dbo.FactVendas e confirme que ela continua íntegra e sem modificações.
⚠️ Atenção para o Exame DP-700:
Conceito de Prova: No Microsoft Fabric, o comando CLONE TABLE opera como Shallow Clone (cópia lógica instantânea de metadados). Apenas quando o clone sofre escrita é que novos arquivos de dados são gerados isoladamente.

Pontos Críticos para a Prática e para o Exame DP-700

📝 Síntese dos Pontos Críticos Aprendidos:

  1. Transformações Vetorizadas no Spark: O Native Execution Engine vetorizado em C++ executa operações relacionais em memória sem a sobrecarga do compilador JVM.
